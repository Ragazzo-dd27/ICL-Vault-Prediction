# Additive Fusion Cross-Split Leakage Audit

## 1. Motivation

This audit checks whether the current global frozen additive alpha, `alpha = 0.35`, selected from pooled matched validation predictions across five repeated outer splits, is strictly independent of every reported outer-split test set.

This audit does not question the resolved alpha semantics. The frozen additive formula remains:

`pred_additive = 0.35 * pred_measurement + 0.65 * pred_as_oct`

Alpha semantics: Measurement weight.

No model was trained, no CNN inference was run, no RF/G2 experiment was rerun, no alpha search was changed, no prediction CSV was modified, and the manuscript was not modified.

## 2. Global Alpha Selection Provenance

The frozen alpha was generated by `scripts/audit_v5_2_matched_fusion_interaction.py`, in `additive_alpha_search()`.

The code path is:

1. `load_matched_validation()` reads:
   - `artifacts/v5_2_matched_unimodal/measurement/measurement_matched_validation_predictions.csv`
   - `artifacts/v5_2_matched_unimodal/as_oct/as_oct_matched_validation_predictions.csv`
2. For each split seed, validation rows are matched by `split_seed` and `sample_id`.
3. The five validation sets are concatenated into one pooled eye-row objective.
4. `additive_alpha_search()` evaluates the frozen grid `[0.0, 0.05, ..., 1.0]`.
5. Formula used in the objective:

   `pred = alpha * measurement_pred + (1 - alpha) * as_oct_pred`

6. Selection metric:

   pooled matched validation MAE.

7. Tie rule:

   choose the largest alpha within `0.5 um` of the best pooled validation MAE.

8. The selected alpha is written to:

   `artifacts/v5_2_matched_fusion_audit/additive_fusion_frozen_alpha.json`

The pooled validation objective used 280 validation eye rows:

| split_seed | validation rows |
| ---: | ---: |
| 42 | 56 |
| 1001 | 56 |
| 2002 | 56 |
| 2026 | 56 |
| 3407 | 56 |

The pooling was performed at eye-row level, not patient level. Each validation appearance contributed one row to the pooled MAE objective.

Pooled validation composition:

- total validation rows: `280`
- total unique patients in pooled validation: `111`
- total unique eyes in pooled validation: `204`
- duplicated validation patient appearances across seeds: `39`
- duplicated validation eye appearances across seeds: `76`

No direct test prediction rows are read by `additive_alpha_search()`. However, because repeated outer splits rotate patients/eyes through train/validation/test roles, the pooled validation set can include patients/eyes that are test patients/eyes in another outer split.

## 6. Test-vs-Pooled-Validation Contamination Check

Main question:

Did any patient or eye in the test set of an outer split also contribute a label to the pooled validation objective used to choose global alpha=0.35?

Answer:

Yes.

Every formal test split has patient-level and eye-level overlap with the pooled validation objective used to choose the global alpha.

Important interpretation:

- This does not invalidate the unimodal predictions.
- This does not mean same-split validation and test were mixed; same-split val/test overlap is zero.
- This does not show direct use of same-split test labels inside `additive_alpha_search()`.
- It does mean the globally pooled validation-selected alpha is not strictly independent of every reported repeated outer test set, because some test eyes/patients in each split contributed labels when they appeared in validation roles in other splits.

## 7. Existing Nested / Per-Split Additive Protocols

Repository search found an existing leakage-safe nested fixed-alpha diagnostic in:

- `scripts/run_v5_2_gate_learnability_diagnostic.py`
- `docs/experiments/v5_2_gate_learnability_diagnostic_report.md`
- `artifacts/v5_2_final_summary/v5_2_gate_summary.csv`

Protocol:

- uses matched validation predictions only
- reads zero test prediction rows
- performs patient-grouped nested cross-validation within each outer validation split
- chooses alpha on the training folds only
- evaluates `nested_fixed_alpha` out-of-fold on held validation folds

Stored result:

- Nested fixed alpha OOF MAE: `164.10 +/- 23.28 um`

This is leakage-safe as a validation-only diagnostic, but it is not an already available formal outer-test additive comparator. I did not promote it to a new formal result.

No existing formal outer-test protocol was found that selects alpha separately within each outer split's validation set and then evaluates only that split's test set.

## 8. Audit Decision

**CROSS-SPLIT ROLE CONTAMINATION DETECTED**

The global pooled validation alpha-selection protocol is not strictly independent of every reported outer-split test set.

## 9. Consequences for Current Additive Result

The current result:

- corrected additive repeated MAE approximately `167.91 +/- 24.56 um`
- wins vs matched best unimodal `3/5`

should not be treated as the final unbiased formal repeated-test additive result without a protocol correction.

It can still be described as a globally pooled validation-tuned diagnostic result, provided the cross-split role overlap is explicitly disclosed. It should not be used as the definitive leakage-clean repeated-split fusion result.

This finding does not affect:

- the resolved alpha semantics
- the unimodal prediction validity
- the matched cohort alignment checks
- the fact that same-split validation/test separation was clean
- the diagnostic conclusion that oracle complementarity does not automatically imply learnable complementarity

## 10. Recommended Next Action

Do not automatically correct results in this audit.

Recommended correction protocol:

For each outer split independently:

1. Use only that split's validation predictions and validation labels.
2. Use the original frozen alpha grid `[0.0, 0.05, ..., 1.0]`.
3. Use the original formula: `alpha * Measurement + (1 - alpha) * AS-OCT`.
4. Use the original validation MAE selection metric.
5. Apply the original tie rule, or explicitly freeze a pre-declared tie rule before recomputation.
6. Freeze that split-specific alpha.
7. Evaluate only on that split's test predictions and labels.
8. Report repeated-split additive MAE and all downstream comparisons from the split-specific alpha protocol.

This correction should use existing unimodal prediction CSVs only. It should require no model training, no CNN inference, no RF rerun, and no G2 rerun.
