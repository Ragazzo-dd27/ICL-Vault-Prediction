# Additive Fusion Alpha Semantics Resolution

## 1. Conflict Discovered

The frozen additive fusion alpha in `artifacts/v5_2_matched_fusion_audit/additive_fusion_frozen_alpha.json` is `0.35`, but two incompatible interpretations were found:

- Formula A: `pred = 0.35 * Measurement + 0.65 * AS-OCT`
- Formula B: `pred = 0.35 * AS-OCT + 0.65 * Measurement`

This resolution does not choose between formulas using test performance. It resolves the alpha provenance from the original generation code, frozen validation artifact, and validation-only recomputation.

## 3. Original Alpha Generation Lineage

The frozen alpha was generated by `scripts/audit_v5_2_matched_fusion_interaction.py`, in the function `additive_alpha_search()`.

In that function:

- `m = val["measurement_pred_um"]`
- `a = val["as_oct_pred_um"]`
- The grid formula is `pred = alpha * m + (1 - alpha) * a`

Therefore, in the original generation code, `alpha` is the Measurement prediction weight.

The script then writes:

- `artifacts/v5_2_matched_fusion_audit/additive_fusion_validation_search.csv`
- `artifacts/v5_2_matched_fusion_audit/additive_fusion_frozen_alpha.json`

`git blame` attributes the original `additive_alpha_search()` formula to commit `9253009e` (`Complete matched fusion cohort interaction audit`, 2026-07-28). The later G2 script is currently untracked in this working tree, so no committed blame record is available for that file.

## 4. Original Fusion Formula

The resolved original formula is:

`pred_additive = alpha * pred_measurement + (1 - alpha) * pred_as_oct`

With frozen `alpha = 0.35`, this is:

`pred_additive = 0.35 * pred_measurement + 0.65 * pred_as_oct`

Thus, alpha means Measurement weight, not AS-OCT weight.

## 5. Validation-Only Recomposition

Using only the original matched validation prediction CSVs and the frozen alpha value:

| Check | Validation MAE |
|---|---:|
| Stored search artifact row for alpha = 0.35 | 162.41260760111930 |
| Formula A: 0.35 * Measurement + 0.65 * AS-OCT | 162.41260760111930 |
| Formula B: 0.35 * AS-OCT + 0.65 * Measurement | 167.12097049327605 |
| Stored search artifact row for alpha = 0.65 | 167.12097049327588 |

Formula A reproduces the original validation selection artifact exactly. Formula B does not reproduce the alpha=0.35 row; it reproduces the original grid behavior of alpha=0.65, which is the same numeric mixture expressed with the opposite alpha semantics.

The original validation protocol was pooled matched validation MAE over the grid `[0.0, 0.05, ..., 1.0]`. The minimum validation MAE occurred at alpha `0.20` with MAE `162.11223373178316`. The frozen alpha `0.35` was selected by the scripted tie rule: choose the largest alpha within `0.5 um` of the best validation MAE.

This freeze was part of the validation search and was applied before the split-level test evaluation in `interaction_outputs()`.

## 6. Which Implementation Is Correct

For the frozen v5.2 matched additive fusion artifact, the correct implementation is Formula A:

`pred_additive = 0.35 * pred_measurement + 0.65 * pred_as_oct`

This conclusion is based on the original generation code, the frozen validation-search artifact, and validation-only recomputation. It is not based on test MAE.

## 7. Which Implementation Introduced Semantic Inversion

The semantic inversion appears in `scripts/run_reliability_aware_gate_experiment.py`:

`fixed_additive_pred = alpha * as_oct_pred_um + (1 - alpha) * measurement_pred_um`

That implementation interprets the same frozen alpha as AS-OCT weight. Because the source frozen alpha was Measurement weight, this reverses the intended additive comparator semantics.

`scripts/summarize_reliability_aware_gate_formal.py` propagates the fixed-additive columns from the formal G2 archive, but it does not appear to introduce the inversion itself.
